# 生成算法说明

1. 浏览器将原图按用户裁剪框缩至目标豆格；透明模式保留输入图已有的透明区域。
2. 每格 sRGB 转 Lab。相邻格亮度与色彩变化较大的位置得到更高权重。
3. 在用户允许的实际色号中，先以加权 CIEDE2000 误差贪心选出至多 `K` 色；再做一轮 add/swap 中的 **swap** 局部改进。计算进入 Dedicated Web Worker。
4. 固定色号集合后逐格匹配。清晰模式谨慎移除非边缘孤点；均衡模式略加强清理；照片模式保留纹理并以低强度误差扩散表现渐变。
5. 手工编辑后重新统计数量。空格标记为 `-1`，与白色或透明材质的豆子不同。

这是一套浏览器友好的近似求解，并不保证复杂图像全局最优。色卡 RGB 本身也只是屏幕参考值。极小五官、文字和杂乱背景仍可能需要用户调大尺寸、调整裁剪或逐格修正。默认不做自动抠图，也不使用会创造原图细节的生成式超分辨率。

## 质量验证

仓库测试目前覆盖：Sharma 参考色差样例、颜色数与允许色号约束、透明空格、面部小深色细节、色卡完整性。浏览器样图验证了移动端上传、生成、编辑、撤销和材料统计。

报告提出的“均衡版相对简单基线 ≥70% 盲测偏好”和“满意度中位数 ≥5/7”需要多类型真实照片与用户评价。**目前尚无这些数据，不应当对外声称图纸效果优于竞品。** 后续应固定照片、插画、像素画等样本，在相同格数、色卡与颜色上限下盲测，并记录小色块数量、孤立豆率、色差及主观可拼性。
